sharing data between components:
---------------------------------
1. if one component (nested/child) is nested in another (parent)
	a. how to pass data from parent to its nested component
		- data binding
	in nested component create a property 
	decorate the property with @Input() decorator

	or
	in nested component create a property by calling input() method which creates a signal based @Input() decorated property (actual type InputSignal<T>)

	pass data from parent component by binding the same to the @Input() decorated property of the nested component (use property binding syntax)

	
	b. how to pass data from nested to its parent component
	- event binding

	in nested component create a property and assign it an instance of type EventEmitter<T>
	decorate the property with @Output() decorator

	or
	in nested component create a property by calling output() method which creates a signal based @Output() decorated EventEmitter type property (actual type OutputEmmiterRef<T>)

	emit the T type value by triggering the event
	handle the event in parent component template by binding the same with a method from parent component

2. if two components are in separate component tree (not nested)

lifting the state up

Pipes:
--------------
transformer

@Pipe({ name: 'uppercase'})
export class UppercasePipe implements PipeTransform{
	transform(value:string,...args:any[]):string{
		return value.toLocaleUpperCase();
	}
}

code:
imports:[UppercasePipe, CurrencyPipe]

template:
person.name|uppercase

	=> new UppercasePipe().transform(person.name)

person.salary|currency:'USD':'2'

	=> new CurrencyPipe().transform(person.salary,'USD','2')


Services and DI:
--------------------------
a place where you can write re-usable piece of logic: business, data access logic etc.


1. create:
------------------
interface Service{
	getData():string[];
}
class DataService implements Service{
	getData(){
		return []
	}
}

2. register a provider for the service
-------------------------------------------------

Register at:
A. Component level 
@Component({
	providers: [//register here]
})

B. Root Level (in app.config.ts file)
export const appConfig:ApplicationConfig={
	providers:[//register here]
}

provider object:
-------------------------
base type:      	Provider
class provider: 	ClassProvider
			provide, useClass

value provider: 	ValueProvider
			provide, useValue

existing provider: 	ExistingProvider
			provide, useExisting

factory provider: 	FactoryProvider
			provide, useFactory

create a provider object:
-----------------------------
a. token is same as that of the class name
example: class provider
{
	provide: DataService,
        useClass: DataService
}

b. token is a string
example: class provider
{
	provide: 'TOKEN',
        useClass: DataService
}

c. token is an InjectionToken type object

const TOKEN = new InjectionToken<Service>('TOKEN')
{
	provide: TOKEN,
        useClass: DataService
}

3. consume the service
---------------------------------
	a. through constructor 
	i. when the token name is same as that of the class name
	constructor(private ds:DataService){}

	ii. when the token is some string value
	constructor(@Inject('TOKEN') private ds:Service){}

	iii. when the token is an InjectionToken type object:
	constructor(@Inject(TOKEN) private ds:Service){}

	b. using inject() method

	i. when the token name is same as that of the class name
	private ds = inject(DataService)

	ii. when the token is some string value
	not possible to have DI through inject() method

	iii. when the token is an InjectionToken type object
	private ds = inject<Service>(TOKEN)

life-cycle of a component:
-------------------------------
a component gets destroyed
	when its parent component gets destroyed
	when the component is "unmounted" from the browser

1. mounting
	a. constructor called
	b. changes event (optional- for the very first time as well every time the nested component receives data from parent through an inout property) -> ngOnChanges
	c. init event (for the very first time when the component is created after constructor and changes event) -> ngOnInit

	component is rendered in the UI (DOM)

2. update
	b. changes event (optional)

3. destroy
	destroy event	-> ngOnDestroy


event-name	interface-name		method-name
------------------------------------------------------
X		OnX			ngOnX
changes		OnChanges		ngOnChanges
init		OnInit			ngOnInit
destroy		OnDestroy		ngOnDestroy
